Read-only, non-root, root-owned-files proofs on orchestrator:dev, run on this
host before any cluster rollout. Every command below runs the container with
--read-only and --user 65532:65532, so the container starting at all is the first
proof that the image needs no writable root filesystem.

The ownership proof the author asked for: the application files are owned by root
and only readable by the app user, so the process cannot modify its own code or
its own dependencies even where the filesystem is writable.

$ docker run --rm --read-only --user 65532:65532 orchestrator:dev sh -c id -u; ls -ld /app /app/.venv; touch /app/x; touch /x
65532

exit=1
