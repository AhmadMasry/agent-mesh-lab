Each template also sets `automountServiceAccountToken: false` at the pod spec level.
No workload of ours talks to the Kubernetes API -- the agents serve A2A, the fixtures
speak HTTP to each other and to the mock -- so the ServiceAccount token the kubelet
mounts by default is a credential with no reader, and the three lab pods should carry
no kube-api-access-* volume after the rollout. Checked there, not here.

The three Job templates -- loadgen-job.yaml, loadgen-a2-job.yaml,
replay-job.yaml -- carry the same three blocks and do not appear in any render:
they are deliberately not listed in the base kustomization, because a Job in an
overlay would run on every apply. Each experiment script substitutes its
variables and pipes the template to `ko apply -f -`, so the blocks reach the
cluster with the Job. Proved by running one: see the clean-check and the
re-count in the findings entry.
