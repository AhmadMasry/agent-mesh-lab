The final stage's one-layer OS upgrade, and what it did on 2026-09-10.

The layer, run before the nonroot user is created and before anything of ours is
copied in:

    RUN apt-get update \
        && apt-get -y upgrade --no-install-recommends \
        && apt-get clean \
        && rm -rf /var/lib/apt/lists/*

Read from a `docker build --pull --progress=plain` of agents/orchestrator/Dockerfile.

Packages upgraded: NONE. "0 upgraded, 0 newly installed, 0 to remove and 0 not
upgraded" is the counted result, and it is the answer rather than a disappointment:
the python:3.14-slim tag, resolved by --pull on this date, already carries the
current patch level of Debian 13 trixie. Both the trixie-updates and the
trixie-security indexes were fetched (47.3 kB and 43.4 kB of InRelease, 4424 B and
257 kB of arm64 Packages), so the upgrade was calculated against security updates
that were actually present, not skipped.

The layer is kept even though it changed nothing today: the tag floats, and the day
the base image lags a security update behind the archive is the day it applies one
without the Dockerfile changing.

Size delta of the layer: the layer's own size is what `docker history` reports for
it below. `apt-get clean` and the `rm -rf /var/lib/apt/lists/*` run in the same
RUN, so the ~10 MB of package indexes apt downloaded do not survive into the image;
what is left is the small amount of apt state the update writes elsewhere.

    20.5kB  RUN /bin/sh -c apt-get update     && apt-get -y upgrade --no-install-recommends     && apt-get clean     && rm -rf /var/lib/apt/lists/* # buildkit

the image content changed by letting the tags float on this date; that is a fact of
