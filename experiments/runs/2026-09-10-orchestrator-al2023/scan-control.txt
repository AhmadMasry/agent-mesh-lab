What this supports, and what it does not
----------------------------------------
Supports: the scanner reads this image's identity. scan/orchestrator.json carries
  distro {"name":"amazonlinux","version":"2023"}, which it can only have got
  from the /etc/os-release that system-release owns -- the file the Dockerfile
  keeps on purpose. And the scanner is not broken on this date: the same version
  4.0.14 with the same 2026-09-10 database counted 170 matches on the
  python:3.14-slim image this one replaces, and 5 on the Go images before the
  module move (experiments/runs/2026-09-10-images-rebuilt/scan/summary.csv).

Does not support: a claim that all 45 packages of the assembled root were
  enumerated and each found clean. A report with an empty `matches` array says
  nothing about how many packages it walked, and neither control discriminates:
  the AL2023 base and Amazon Linux 2 both answer 0 as well, so this database has
  no open match for any Amazon Linux image reachable from here today. The counted
  result is therefore exactly "0 matches against the 2026-09-10 database", and
  nothing stronger is claimed from it.
