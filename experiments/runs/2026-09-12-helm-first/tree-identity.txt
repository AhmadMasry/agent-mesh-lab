# tree-identity.txt -- which tree each rebuild built, stated by IDs that survive a history rewrite.
# Written 2026-09-12 in fix round 2.
#
# Why this file exists. The branch was rewritten twice by `git rebase -i --autosquash` (fix round 1,
# then fix round 2). A rewrite gives every rewritten commit a new SHA, and the old SHAs stop being
# reachable from any branch once the local safety refs are deleted. Several records, and some commit
# messages, cite commit or tree SHAs from before a rewrite. A git object ID of a TREE or a BLOB,
# however, depends only on content: if the deployed files are unchanged by a rewrite, their subtree
# and blob IDs are unchanged too, and they stay resolvable from the pushed branch forever. So the
# identity of what each rebuild built is recorded here as the subtree ID of every deployed path, and
# each claim below can be checked against the pushed branch with the commands in section 4.
#
# The deployed paths are the ones `make step-1 … step-3` read: deploy/, Makefile, agents/, fixtures/,
# experiments/lib, experiments/*.sh, and the build inputs .ko.yaml, go.mod, go.sum, internal/ and
# kind-config.yaml.
#
# Commits are named here by SUBJECT, which a rewrite does not change, and by position on the branch.
# The head's own SHA is never listed: this file lives in the branch, and any rewrite that carries it
# changes that SHA. Identity is by subject order and subtree IDs.

## 4. How to check every claim above against the pushed branch
#
#   subject → commit:   git log --format='%h %s' <base>..<branch>

#                       :experiments/lib, :.ko.yaml, :go.mod, :go.sum, :internal, :kind-config.yaml)
#   a script's blob:    git rev-parse <commit>:experiments/gate2-single-clean.sh   (and each other .sh)
#   rebuild #1:         every section 1 ID equals `git rev-parse <commit "build(deploy): drop the three
#                       telemetry manifests…">:<path>`
#   rebuild #2:         every section 2 ID equals `git rev-parse <last commit>:<path>`
