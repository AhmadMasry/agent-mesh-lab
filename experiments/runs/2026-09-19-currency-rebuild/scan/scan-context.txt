Read as it is rather than as one would like it: the ko image IDs above do NOT
equal the ones the pods run. This repository has measured before
(experiments/runs/2026-09-09-a3-pipeline/replicasets.txt, and the comments on
step-2c and step-3 in the Makefile) that ko rebuilds unchanged sources to a new
digest on every apply, so a rebuild for a scan cannot reproduce the digest a
previous apply loaded. What is equal is the input: the same checkout, the same
.ko.yaml base tag resolved to the same index digest, and the same toolchain.
The orchestrator's two identifiers differ for a different reason and are the SAME
BUILD: `kind load docker-image` re-imports into the node's containerd store,
which computes its own digest over the imported archive, so the pod reports an
import-<date>@sha256:... reference while the daemon holds the build's own id.

Files
-----
<image>-findings.csv is the per-finding record, one row per counted finding,
columns id,severity,package,version,fixed_in,type, sorted by severity then id.
fixed_in is EMPTY when the report carries no fix -- nothing to upgrade to --
which is the column the findings entry's Interpretation counts. Derived from
<image>.json by experiments/lib/kubescape-findings.jq, which is what this script
runs; the program's own comments explain the columns and why the fields need no
quoting.

The row count of each CSV equals that image's total in summary.csv, and their
per-severity counts equal its columns.

What Kubescape wrote for this scan, read from the files themselves rather than
stated as a fixed fact -- a report's size follows its match count, and both move
with the image and the database date:
  worker            10912 bytes       0 matches
  mockllm           10928 bytes       0 matches
  loadgen           10928 bytes       0 matches
  replay            10915 bytes       0 matches
  orchestrator       5715 bytes       0 matches

Which of those JSON reports is committed is not this script's statement to make.
CLAUDE.md keeps run outputs to small CSV or JSONL, so that is a decision of the
commit carrying this run, and its message is where it is recorded. What this file
can say is the two numbers above, that `make scan-images` regenerates every
report, and that each <image>-findings.csv is derived from its own <image>.json
and carries every finding in it whether that JSON is committed or not.
