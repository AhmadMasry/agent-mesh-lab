   | ## Summary
   | 
   | The agentgateway controller does not set `tunnel_protocol` on Bind resources for HBONE or `istio.io/PROXY` listener protocols. This prevents agentgateway from acting as an Istio ambient mesh waypoint proxy, even though the Rust proxy already has full support for both tunnel modes.
   | 
   | ## Problem
   | 
   | ### 1. `istio.io/PROXY` is not a supported listener protocol
   | 
   | In `conversion.go`, `listenerProtocolToAgw()` only accepts HTTP, HTTPS, TLS, TCP, and HBONE. A Gateway listener using `protocol: istio.io/PROXY` (the standard Istio protocol for third-party waypoints on port 15088) is rejected with:
   | 
   | ```
   | protocol "istio.io/PROXY" is unsupported
   | ```
   | 
   | ### 2. `tunnel_protocol` is never set on Binds
   | 
   | In `syncer.go`, `getBindProtocol()` maps listener protocols to `api.Bind_Protocol` values but **never sets the `TunnelProtocol` field**. It always defaults to `Bind_DIRECT` (0).
   | 
   | For waypoint proxies, ztunnel sends traffic using:
   | - **HBONE** (port 15008): HTTP/2 CONNECT over mTLS — requires `TunnelProtocol: HBONE_WAYPOINT` so the proxy terminates the HBONE tunnel
   | - **PROXY protocol v2** (port 15088): binary header with source identity in TLV 0xD0 — requires `TunnelProtocol: PROXY` so the proxy parses the PROXY header
   | 
   | Without the correct `tunnel_protocol`, the proxy starts a plain HTTP bind and cannot parse the tunnel framing from ztunnel.
   | 
   | ### 3. Rust proxy already supports both modes
   | 
   | The proxy's `handle_tunnel()` in `gateway.rs` dispatches based on `TunnelProtocol`:
   | - `TunnelProtocol::HboneWaypoint` → `terminate_waypoint_hbone()` (mTLS + HTTP/2 CONNECT)
   | - `TunnelProtocol::Proxy` → `terminate_proxy_protocol()` (PROXY v2 header parsing, TLV 0xD0 identity extraction)
